EZ Healthcare

An accessible healthcare mobile application being developed for older adults and users with visual, hearing, or mobility limitations.

Project Type: Team Capstone Project — In Progress

My Role: Lead Developer

← Back to Selected Work

Project Overview

EZ Healthcare aims to make common healthcare tasks easier to navigate. The team is designing an interface with large buttons, clear labels, accessible visual settings, and minimal steps.

The planned application brings medication information, appointments, provider information, and emergency assistance into an interface focused on accessibility. Development is ongoing.

My Role

As lead developer, I help implement the application, organize its code, and make architecture decisions. My work has included scaffolding the React Native application with Expo and TypeScript, implementing prototype screens, and testing API connectivity.

Current Progress

  • A React Native, Expo, and TypeScript application scaffold with Expo Router navigation.
  • Prototype welcome, login, home, and accessibility settings screens.
  • The application has been launched in an Android emulator.
  • A successful request to the Epic FHIR sandbox capability endpoint returned HTTP 200.
  • Backend and database setup work has begun.

The Epic sandbox test established that the endpoint could be reached and its response processed. Patient sign-in and access to patient records require additional implementation and testing.

Planned Features

  • Medication information and reminders.
  • Appointment management.
  • Health information display.
  • Healthcare provider directory.
  • Emergency assistance.
  • Accessible text, visual settings, and simple navigation.

Technologies and Tools

  • React Native: Mobile application interface.
  • Expo: Development workflow and Android testing.
  • TypeScript: Application code.
  • Expo Router: Screen navigation.
  • Epic FHIR Sandbox: Healthcare API feasibility testing.
  • Figma: Interface design and prototypes.
  • Git and GitHub: Version control and team coordination.

Accessibility Approach

Accessibility guides the interface design from the beginning. The team is prioritizing readable text, clear controls, understandable language, and short navigation paths.

The prototype still needs user testing to evaluate whether these choices help the intended audience complete healthcare tasks independently.

Next Steps

Upcoming work focuses on connecting the planned feature screens to the backend, continuing Epic integration testing, and refining the interface through feedback. Medication, health information, provider, appointment, and emergency screens are part of the next development work.
